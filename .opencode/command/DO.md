# /DO 工作流

**任务：** $OPENCODE_SHARE

---

## 第零阶段：信息源分类（当前 session，秒级完成）

根据任务快速判断需要哪几类信息，分为以下四类，**只选需要的类**：

| 类别 | 内容 | Task 标签 |
|------|------|-----------|
| A. 代码结构 | 目录结构、类/函数定义、文件列表、模块划分 | `STRUCT` |
| B. 实现细节 | 核心文件内容、方法实现、关键逻辑 | `IMPL` |
| C. 测试 & 配置 | 测试文件、配置文件、schema、序列化数据 | `TEST_CFG` |
| D. 依赖关系 | 被谁引用、依赖谁、接口定义、事件/回调 | `DEPS` |

---

## 第一阶段：并行多 Task 收集（Gemini Flash × N）

**同时**派发所有需要的 Task，每个 Task 使用 `google/gemini-flash-latest`，独立专注一类信息。

💡 **Unity 逆向工程极致优化**：如果是实现或修改 C# 类，请**直接调用 `unity-rag-retriever` 工具**（传入 `projectDir` 和 `className`）来获取原版 `dump.cs` 结构和依赖关系，而无需让子 Agent 盲搜。

### Task A — 代码结构收集
```
[STRUCT] 任务：$OPENCODE_SHARE

专注收集代码结构信息：
1. 列出所有相关目录和文件（路径+用途一句话）
2. 找到所有相关的类定义（类名、继承关系、所在文件:行号）
3. 列出关键的 public 方法签名（方法名、参数、返回值、所在文件:行号）
4. 识别模块/命名空间划分
5. 找到入口点和主要流程节点

输出：结构化的代码地图，精确到文件:行号
```

### Task B — 实现细节收集
```
[IMPL] 任务：$OPENCODE_SHARE

专注收集核心实现内容：
1. 读取最相关的 3-5 个核心文件的关键方法实现
2. 提取关键算法和业务逻辑代码片段（含文件:行号）
3. 找到任务直接涉及的具体代码块
4. 记录重要的变量、常量、配置值
5. 注意任何 TODO/FIXME/HACK 注释

输出：关键代码片段集合，精确到文件:行号
```

### Task C — 测试 & 配置收集
```
[TEST_CFG] 任务：$OPENCODE_SHARE

专注收集测试和配置信息：
1. 找到所有相关测试文件，列出已有的测试用例名称
2. 读取关键配置文件（JSON/YAML/场景文件等）
3. 找到序列化数据文件和 schema 定义
4. 检查 CI/CD 配置中的相关规则
5. 找到任何 mock/stub/fixture 文件

输出：测试覆盖情况 + 配置值清单，精确到文件:行号
```

### Task D — 依赖关系收集
```
[DEPS] 任务：$OPENCODE_SHARE

专注收集依赖和引用关系：
1. 搜索任务涉及的类/函数被哪些地方调用（反向引用）
2. 找到任务涉及的类/函数依赖的外部接口
3. 识别事件、回调、委托的绑定关系
4. 找到 interface/abstract class 的实现链
5. 识别初始化顺序和生命周期依赖

输出：依赖图谱，精确到文件:行号
```

**等待所有 Task 完成后继续。**

---

## 第二阶段：汇总整合（当前 session）

将各 Task 的输出合并，去重，按以下结构整理：

```
## 汇总上下文

### 代码地图 [来自 STRUCT]
...

### 核心实现 [来自 IMPL]
...

### 测试 & 配置 [来自 TEST_CFG]
...

### 依赖关系 [来自 DEPS]
...

### 发现的问题 / 注意点
（各 Task 发现的风险和注意事项汇总）
```

---

## 第三阶段：分析与计划（Claude Sonnet，当前 session）

基于汇总的上下文，深度分析并输出：

```markdown
## 现状分析
[基于实际代码的现状描述，引用具体文件:行号]

## 实现计划
1. **[步骤标题]**
   - 文件：`path/to/file.ext:行号`
   - 操作：[具体要做什么]
   - 原因：[为什么这样做]

2. **[步骤标题]**
   ...

## 风险与注意事项
- [风险1] → 影响文件:行号 → 应对方案
- [风险2] → 影响文件:行号 → 应对方案

## 需要确认的问题
- [需要用户决策的事项]

## 推荐方案
[一段话，说明最佳路径和理由]
```

**输出计划后停止，等待用户确认后再执行。**
